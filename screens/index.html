VVF 3.0 · Chroma · Revision 3, after the notes · Mobile web, in a browser

Search first. Two questions. Then it starts giving.

Ten screens. The category grid is gone and a search box takes its place, the two questions now ask about goal and problem rather than gear, nothing in the feed is analysed until it is tapped, and the free tier runs out in three separate places instead of one.

Skincare Fitness Food Fashion Home Pets Highlight
Two rules keep it from getting noisy. Coral #FF4F5E is the action colour and never changes, on any screen, in any category. Cyan #25F4EE is the highlight and is never a button, never a link, never text on white. The category hue owns everything else. If a button changes colour, the system is broken.
The cyan is a proposal, not a decision. It is one variable. Swapping it for the sky blue, the lime or the category’s own hue is a one-line change and every screen below follows. The four candidates are on the directions page.

It is a browser, not an app.

Every screen below is drawn inside mobile Safari, address bar included, because that bar is real estate we never get back. Adding it cost three screens a line each. Better to find that here than after the build.

The top 30px are not oursOn a 306×648 frame the address bar takes roughly a twentieth of the screen before we draw anything. Screens 02, 04 and 06 each had to lose a line to fit once it was added.
iOS Safari puts its bar at the bottomWhich is exactly where every primary button on these screens lives. Each one needs safe-area padding or it sits underneath Safari’s own toolbar and cannot be tapped.
There is no pushThe “weekly read on your account” promised on screen 07 has to arrive by email. That is the third separate reason the address on screen 03 is worth asking for.
The first run is a URLNo install, no store, no icon. Somebody taps a link in a bio or a DM and lands cold, which is why screen 01 has to work with no context and no prior session.
100vh lies hereThe layout has to use dvh, or every screen jumps each time the address bar collapses on scroll. It bites hardest on the feed, which is the one screen built to be scrolled.
TikTok connect is a redirectNot an SDK call. They leave the site and have to come back. Deferring it past screen 04 moves the riskiest redirect away from the highest drop-off moment, which is a second argument for the call already made.

WHAT THE CAPS ARE FOR

Three separate limits, three different asks. Eight videos, three searches, five analyses. They run down at different speeds on purpose, so whichever one a person hits first is the one that best describes how they were actually using it.

Videos run out fastest and ask for the least. Someone who has scrolled eight cards has browsed, not committed. That cap offers a sideways move first — spend a search on another category — and only then a join.

Analyses run out slowest and ask for the most. Five analyses is five hooks copied. That person has used the actual product, so that is where the trial goes, not a cold join button.

The counter is on every screen before any of them. The cap should be the moment something runs out, never the moment they learn there was a limit.

NOTES

Photography is still the one real gap. Every thumbnail here is a coloured placeholder, and on screen 05 that hurts more than it did before, because the feed is now a list of thumbnails rather than one full-bleed card. Real frames would change how this reads more than any other single change.

Screen 04 is built from a locked list. Every number on it comes from something retrievable without a TikTok login. The full inventory, including what we would gain from the connect and what it costs to compute, is on its own page.

The connect moved, it did not disappear. It is off the sign-in screen and now sits at the bottom of 04, phrased as “we estimated these, want the real number”. That is a better offer after a finding than before one.

Still open. The three cap numbers, the price, the trial length, and whether we run the video analysis for every signup or only on request. The last one is a cost question and it is the only one that needs an answer before build rather than before launch.
